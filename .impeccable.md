## Design Context

### Users
JavaScript/TypeScript, React, Kotlin/JVM, and Swift developers who need Kenyan administrative data in forms, address pickers, and search. They arrive from npm, Maven, or GitHub, want a working example in under a minute, then copy an API snippet for their platform.

### Brand Personality
Precise, civic, unhurried. The library is a reference for real places — counties, wards, estates — not a splashy product launch. Copy should be factual and short. The site should feel like a well-kept public register, not a SaaS landing page.

### Aesthetic Direction
Use [coss ui](https://coss.com/ui) as the visual system: Base UI primitives, Tailwind v4 tokens, dense production UI in the Cal.com lineage. Light by default (read during the day, beside an editor) with a dark theme that uses the same tokens. Neutral surfaces, sharp type hierarchy, no gradient text, no hero-metric templates, no emoji-as-logo.

Anti-references: generic shadcn marketing pages, purple/cyan AI palettes, centered card grids, flag-color overload.

### Design Principles
1. **coss first** — components, spacing, and tokens come from coss ui; customize only where Kenya-locations content needs it.
2. **Show the data** — the explorer is the documentation. Live counties, search, and hierarchy beat another paragraph.
3. **Every platform equally** — JS, React, Kotlin, and Swift get the same quality of examples. The site is not a TypeScript-only brochure.
4. **Left-aligned, scannable** — docs layout with sticky nav, not a centered landing page.
5. **Current API only** — examples match exported functions, types, and versions in this repo. No leftover aliases presented as the primary API.
